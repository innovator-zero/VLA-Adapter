# LIBERO-plus evaluation

The Plus entry point uses VLA-Adapter's existing model loader, normalization,
image preprocessing, action chunks, gripper conversion, and episode loop.
Horizons are 220/280/300/520 steps for Spatial/Object/Goal/Long, plus the default
10 settling steps. Each task runs **one episode by default**.

Activate an environment with the VLA-Adapter and LIBERO-plus dependencies.
Install the pinned simulator dependencies in that environment:

```bash
python -m pip install -r experiments/robot/libero/libero_requirements.txt
```

Use `mujoco==3.2.3` with `robosuite==1.4.1`. MuJoCo 3.13.0 changes enum
comparison behavior and can trigger the joint-type assertion in
`robosuite/utils/binding_utils.py` during environment creation.

Set `LIBERO_PLUS_ROOT` to a complete checkout containing
`libero/libero/benchmark/task_classification.json`, BDDL files, initial states,
and assets. The default checkout is `third_party/LIBERO-plus` in this repository.
The entry point creates an isolated, non-interactive LIBERO config under the
output directory and selects the Plus checkout before importing the simulator.
No sibling X-VLA/openpi repository is needed.

From the repository root:

```bash
export LIBERO_PLUS_ROOT=/path/to/LIBERO-plus

CUDA_VISIBLE_DEVICES=0 bash experiments/robot/libero/eval_libero_plus.sh \
  libero_spatial adapter_pro --pretrained_checkpoint outputs/LIBERO-Spatial-Pro

bash experiments/robot/libero/eval_libero_plus.sh \
  libero_object adapter_pro --pretrained_checkpoint outputs/LIBERO-Object-Pro
bash experiments/robot/libero/eval_libero_plus.sh \
  libero_goal adapter_pro --pretrained_checkpoint outputs/LIBERO-Goal-Pro
bash experiments/robot/libero/eval_libero_plus.sh \
  libero_10 adapter_pro --pretrained_checkpoint outputs/LIBERO-long-Pro

# Resume a suite using the same checkpoint and evaluation settings.
bash experiments/robot/libero/eval_libero_plus.sh \
  spatial adapter_pro --pretrained_checkpoint outputs/LIBERO-Spatial-Pro --resume

# Summarize the four suite logs with the same save name.
bash experiments/robot/libero/eval_libero_plus.sh summary adapter_pro
```

Short suite names (`spatial`, `object`, `goal`, `10`) are also accepted. The
wrapper works from any directory; relative checkpoint paths are relative to
your working directory. Model inference runs in this process, so no server
address or port is needed. Activate your environment before launching it.

The Python entry point accepts Plus options and forwards the remaining options
to the existing `GenerateConfig` parser:

```bash
python experiments/robot/libero/run_libero_plus_eval.py \
  --task_suite_name libero_spatial \
  --save_name adapter_pro \
  --pretrained_checkpoint outputs/LIBERO-Spatial-Pro \
  --num_trials_per_task 1 \
  --use_pro_version True \
  --save_video False \
  --resume
```

Use the model options appropriate to your checkpoint, as for ordinary LIBERO
evaluation (including `--use_pro_version False` for the original model).
Plus-specific flags are `--save_name`, `--output_dir`, `--libero_plus_root`,
`--libero_config_path`, `--classification_path`, `--resume`, and `--summary_only`.
`--resume` and `--summary_only` are bare switches; model boolean options use
`True`/`False`. Plus evaluation uses the benchmark's default initial states;
custom `--initial_states_path` files are rejected. Trial counts must not exceed
the number of available initial states.

## Saved results

The default output directory is `experiments/logs/libero_plus` under the
repository root, independent of the working directory. Override it with
`--output_dir`. It contains:

- `results/<save_name>_plus_<suite>_tasks.jsonl`: one record per fully completed
  task, including task/classification IDs, category, episodes, successes and
  success rate. Each completed task is saved by atomic file replacement.
- `results/<save_name>_results.md`: appended suite/category reports after each
  completed suite invocation.
- `results/<save_name>_plus_category_summary.md`: regenerated by `summary`, with
  per-suite category counts/rates, suite totals, all-case totals, and four-suite
  category means. The schema and calculations match the openpi/X-VLA reports.
- `logs/<save_name>/<suite>/EVAL-*.txt`: timestamped native evaluation logs.
- `videos/<save_name>/<suite>/task_<id>_episode_<n>_success_<0|1>.mp4`: optional
  videos when `--save_video True`; rerunning the same task/outcome replaces its video.
- `.libero-plus-config/config.yaml`: generated LIBERO paths, unless overridden.

Resume skips tasks whose recorded episode count matches the requested count;
changed counts rerun the task. An interrupted task reruns from its first episode.
Inference/simulation errors propagate so the task is not recorded as completed;
its environment and log file are closed. A fully completed resumed suite skips
checkpoint loading. Without `--resume`, the selected suite's task log is reset.
Use a new save name when changing checkpoints, seeds, or other evaluation settings.

Summary requires all four task-log files and warns about incomplete coverage.
Suite and all-case rates divide successes by logged episodes; category means
weight each of the four suites equally. As in the reference reports, a category
without logged episodes contributes 0% to the four-suite mean.

Summary mode needs only Python's standard library, the classification JSON,
and the task logs; it does not import LIBERO, Torch or model dependencies:

```bash
python experiments/robot/libero/run_libero_plus_eval.py \
  --summary_only --save_name adapter_pro \
  --classification_path /path/to/task_classification.json
```

## Regression tests

```bash
python -m unittest discover -s experiments/robot/libero -p 'test_libero_plus.py' -v
```

These tests use fake environments/models to exercise persistence, resume,
resource cleanup, report calculations and the offline CLI. Real policy success
rates require the evaluation environment and an appropriate checkpoint.
